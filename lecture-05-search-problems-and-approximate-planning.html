Search problems, reusable futures, and approximate planning

A planner can explore more paths, remember solved states, or discard candidates. These choices buy different forms of efficiency and lose different guarantees.

Independent enhanced chapter accompanying Percy Liang's Search I recording. The sequence and timestamp links follow machine transcription. The constrained travel case, proofs, counterexamples, exercises, and runnable program are original teaching constructions. The pinned official executable lecture and checked research are cited beside their supported claims.

1. Choosing a sequence requires a model of what follows 00:05

A traveler must reach a meeting before a deadline. Walking is reliable, a tram can skip locations, tickets are limited, and the route may prohibit consecutive tram rides. Choosing a locally attractive action can leave the traveler unable to finish. The output should be a complete feasible route and its total cost, rather than a prediction of which action looks good at the current location.

Planning chooses actions using a model of their consequences. Search explores possible sequences in that model. A learned predictor can supply a transition model, a cost estimate, or a policy that proposes actions; search then uses those objects. The search result is only as meaningful as the stipulated model and objective. Finding a least-cost route in a graph does not certify that its tram exists or that a predicted travel time is accurate.

The lecture motivates a combination of learning and computation rather than a rigid boundary between them. We will distinguish three questions throughout: what information defines a state, which complete sequences the algorithm can reach, and what score it minimizes among those sequences. A failure in the first two questions cannot be repaired by sorting candidates more accurately.

Chapter 1's observations, objectives, and actions are useful background. Chapter 3's text representation provides another warning: compressing an input can erase information needed for the eventual decision. All search objects needed here are defined locally.

2. Separate the problem from the algorithm 05:16

A finite deterministic search problem consists of a finite state set \(S\), a start state \(s_{\mathrm{start}}\in S\), a terminal or goal set \(G\subseteq S\), and a finite legal-action set \(A(s)\) at each nonterminal state. For each legal action \(a\in A(s)\), the successor \(\operatorname{Succ}(s,a)\in S\) is deterministic and the edge cost \(c(s,a)\in\mathbb R\) is finite. The algorithms below stop on first arrival at a goal; outgoing edges from goals are therefore irrelevant.

A complete path \(P=(s_0,a_0,s_1,\ldots,a_{L-1},s_L)\) starts at \(s_0=s_{\mathrm{start}}\), follows legal transitions, and first reaches a goal at \(s_L\in G\). Here \(L\) is its number of actions. Its additive cost is

\[C(P)=\sum_{t=0}^{L-1}c(s_t,a_t).\]

The index \(t\) denotes action position. The optimization problem is to minimize \(C(P)\) over complete feasible paths. A partial path that has not reached a goal is not an admissible answer, however small its current cost. If the start is already a goal, the empty action sequence is complete and has cost zero. If no goal is reachable, there is no solution; we represent its optimal value by \(+\infty\), not by zero.

For a concrete case, let locations be the integers \(i=1,\ldots,n\), where \(n\) is the destination location and the traveler starts at 1. Walking sends \(i\to i+1\) at cost one minute. A tram sends \(i\to2i\) at cost two minutes. An action is legal only if its destination is at most \(n\). These costs are stipulated travel minutes, not measured timings.

For \(n=10\), walking throughout requires nine actions and costs nine minutes. The route \(1\to2\to3\to6\to10\) is not feasible: there is no edge from 6 to 10. The feasible route \(1\to2\to3\to6\to7\to8\to9\to10\) costs eight minutes if the first two moves are walks and the third is a tram. A better complete route is \(1\to2\to4\to5\to10\), costing \(1+2+1+2=6\). Local plausibility is not a substitute for checking each edge.

The pinned official search module provides this separation through start, successor, and terminal methods. Our program uses an explicit finite graph and exact rational costs. That representation choice changes the implementation, not the mathematical interface.

3. A state is a promise that the forgotten history will not matter 10:58

In the unconstrained street problem, location alone determines all future legal actions and their costs. Two histories that arrive at the same location face the same remaining optimization problem even if their accumulated costs differ. A search node can store a path and its accumulated cost; a problem state summarizes the future. Treating these as the same object wastes reusable work or discards information needed for correctness.

Now give the traveler \(k_{\mathrm{ticket}}\) unused tram tickets, a nonnegative integer. Each tram consumes one ticket; walking consumes none. A location-only state is insufficient. At location 5 with destination 10, a traveler with no tickets must walk five times, costing five minutes. A traveler with one ticket can take the tram to 10 for two minutes. The same location has different optimal suffixes.

Suppose consecutive tram rides are also forbidden. Introduce \(b_{\mathrm{last}}\in\{0,1\}\), indicating whether the preceding action was a tram. The sufficient state is

\[s=(i,k_{\mathrm{ticket}},b_{\mathrm{last}}).\]

A walk increments location, preserves the ticket count, and resets the bit to zero. A tram is legal only when \(k_{\mathrm{ticket}}\gt0\), \(b_{\mathrm{last}}=0\), and \(2i\le n\); it doubles location, decrements tickets, and sets the bit to one. Every state with \(i=n\) is terminal, regardless of its unused tickets or bit.

Formally, history compression is valid when any two histories mapped to the same state have the same terminal status and matching legal actions, successor states, and incremental costs. By induction on the number of remaining actions, they then have the same feasible suffixes and suffix costs. Their earlier accumulated costs need not match. Additivity lets us compare those prefixes separately from the shared future.

This criterion is relative to the model. A departure-time-dependent tram requires clock information; a fatigue-dependent walk may require fatigue. Enlarging the state restores sufficiency only if the added variables capture the relevant dependency. We have not modeled uncertain travel times or partial observation. A deterministic graph solver cannot infer those missing variables from its search budget.

4. The best future can be decomposed at its first edge 20:33

Define \(F(s)\) as the minimum cost of a complete suffix starting at state \(s\), with \(F(s)=+\infty\) when no such suffix exists. To establish a terminating exact computation, assume the start-reachable graph after making goals absorbing is a directed acyclic graph, abbreviated DAG. A DAG has no directed cycle. Equivalently for a finite graph, we can order its states so every edge points forward. The location coordinate supplies such an order in our travel model because both actions increase it.

\[F(s)=\begin{cases}0,&s\in G,\\\displaystyle\min_{a\in A(s)}\left[c(s,a)+F(\operatorname{Succ}(s,a))\right],&s\notin G.\end{cases}\]

The minimum of an empty set is defined here as \(+\infty\). Adding a finite cost to an unreachable suffix still gives \(+\infty\). These conventions distinguish a dead end from a completed empty path.

Proof. Consider states in reverse topological order. A goal has exactly the empty suffix under the stopping rule. A nonterminal complete suffix must begin with one legal action \(a\). After that action, the remainder is a complete suffix from its successor. By the induction hypothesis, no remainder is cheaper than that successor's \(F\), so no complete suffix is cheaper than the displayed minimum. Conversely, if a candidate has finite successor value, append its attained optimal successor suffix to that first action. This constructs a path with the candidate cost. Taking the best candidate achieves the minimum. If every successor is unreachable, no complete suffix exists.

The proof uses finite acyclic structure and additive costs; it does not require nonnegative edges. A DAG containing \(s\to a\) of cost 3 and \(a\to g\) of cost −5 has optimal cost −2. Negative costs invalidate some later search shortcuts, but they do not invalidate this reverse-order recurrence.

For destination 4, work backward. The goal has \(F(4)=0\). Location 3 can only walk, giving \(F(3)=1\). Location 2 can walk for \(1+1=2\) or tram for \(2+0=2\), so \(F(2)=2\). At location 1, walking gives \(1+2=3\) and taking a tram to 2 gives \(2+2=4\). Thus \(F(1)=3\).

A scalar value does not specify a route. Record one minimizing action beside each finite nonterminal value, then follow those backpointers from the start until a goal. Ties can be broken by fixed action enumeration order without changing optimal cost. Our program orders walking before taking a tram; destination 4 therefore returns the all-walking route, although another route ties it.

5. Exhaustive search expands histories that may share a future 27:09

Exhaustive search visits every legal complete path and chooses the cheapest. On a finite DAG, it terminates because no path can repeat a state. A depth-first traversal can begin at the start, extend the current path by each legal action, and evaluate each arrival at a goal. It must still inspect all siblings before certifying an optimum; the first completed path need not be cheapest.

The destination 4 traversal calls the suffix problem at location 2 once after walking from 1 and again after taking the tram from 1. It also reaches later locations repeatedly. Counting each entered path prefix, including goal entries, gives nine visits while there are only four problem states. These are different counts with different computational meanings.

A standard worst-case bound needs explicit hypotheses. If every prefix has at most \(b\) children and no path exceeds \(h\) actions, the number of entered prefixes is at most \(1+b+\cdots+b^h\), exponential in \(h\) for fixed \(b\gt1\). This bound is attained by a full branching tree. It is not a proof that the specific street graph grows exponentially in its destination index.

A small DAG can nevertheless unfold into exponentially many paths. Construct a start state followed by a positive integer number \(h\) of layers of two states each, with every state connected to both states of the next layer. Both final-layer states are goals. There are \(1+2h\) distinct states, \(2^h\) complete paths, and \(2^{h+1}-1\) entered prefixes in the unfolded traversal. Different histories repeatedly meet the same future.

A streaming recursive depth-first implementation can use workspace proportional to path depth if it keeps only a current path, local iterators, and an incumbent, excluding input graph storage. That is an implementation choice. Our transparent iterative exhaustive routine stores immutable full prefix tuples on its stack; copying and pending siblings consume additional space and time. Its visit counter measures combinatorial expansion, not allocation bytes or wall time.

6. A recurrence, an evaluator, and a finite horizon are different objects 33:19

Add a zero-cost self-loop at state \(s\) and an edge from \(s\) to goal \(g\) costing 5. A naive recursive evaluator that follows the loop first calls itself indefinitely. Memoization does not fix this: the value is not stored until the call returns. The true optimal complete-path cost is still 5.

The cyclic equation \(F(s)=\min\{F(s),5\}\) illustrates another subtlety. Every real value at most 5 satisfies that algebraic equation, but most are not the value of the defined path optimization problem. Merely solving a fixed-point equation without a correct boundary or selection principle does not identify the desired value. The cyclic problem is not automatically meaningless; the acyclic evaluator is inapplicable.

A finite action horizon \(H\in\{0,1,2,\ldots\}\) changes the problem to completion in at most \(H\) actions. Define \(F_h(s)\) for a remaining action budget \(h\). Set \(F_0(s)=0\) at goals and \(+\infty\) elsewhere. For \(h\gt0\), goals retain zero and nonterminals obey the same first-edge recurrence with successor budget \(h-1\). Every recursive call decreases the budget, even when the location does not change.

Introducing a time coordinate without a finite upper bound does not ensure finite search. With a finite horizon, termination is guaranteed for finite branching, but equivalence to the original optimum is not. Destination 10 needs at least four actions in the unconstrained graph. A horizon of 3 therefore returns failure even though complete routes exist with larger budgets.

For a finite graph with nonnegative edge costs, deleting a cycle from a complete path cannot increase its cost and preserves its continuation. Repeating this deletion produces a simple path, one with no repeated states. If a goal is reachable, some optimal path therefore uses at most \(|S|-1\) actions. Here \(|S|\) is the number of states. This provides a sufficient horizon, not a promise that every truncated rollout will reach the goal.

Negative cycles require a different boundary. If a negative-total-cost cycle is reachable from the start before termination and can subsequently reach a goal, traversing it repeatedly gives arbitrarily low complete-path costs. The infimum is \(-\infty\) and no finite optimum exists. A negative cycle in an unreachable component, or one from which no goal can be reached, does not cause that conclusion. Our exact program rejects any start-reachable nonterminal cycle; it makes no claim to solve cyclic shortest paths.

7. Reuse the solved state, then reconstruct one witness 37:20

Memoization stores a function's result under its argument so repeated calls can reuse it. For a sufficient acyclic state, the future-cost function is exactly the reusable object. Once \(F(5)\) has been computed for the unconstrained destination 10 problem, every prefix ending at 5 can use it. Earlier prefix costs remain separate.

Memoized recursion and reverse-topological iteration compute the same recurrence in different orders. Recursion discovers reachable states on demand; a reverse-order solver first identifies the reachable graph and then evaluates each state after its successors. Both need correct state identity. Caching under location alone in the ticket model returns values from the wrong problem, even if the cache itself is implemented perfectly.

Our exact solver returns a scalar future-value map and a reconstructed route. Unreachable values are represented internally by None, avoiding arithmetic with infinite rational numbers. A goal value is the exact rational zero. The solver records only one chosen outgoing edge per finite nonterminal state; it follows these choices after computing the start value.

For destination 10, the exact value is 6. With walk-first tie breaking, our route is \(1\to2\to3\to4\to5\to10\), four walks plus one tram. The shorter-in-action-count route \(1\to2\to4\to5\to10\) also costs 6. Minimizing minutes does not impose a secondary preference for fewer actions. If that preference matters, define a lexicographic objective or another explicit tie rule before reporting a unique optimum.

For destination 17 without constraints, the value is 8. With two tickets and no consecutive trams, the value rises to 9, attained by \(1\to2\to3\to6\to7\to8\to16\to17\). The two tram actions are separated by walks. This difference results from the feasible set, rather than an optimizer failing to find the unconstrained solution.

8. Count values, path records, and representation costs separately 43:22

Let \(V\) and \(E\) denote the numbers of start-reachable states and outgoing edges after making goals absorbing. Under unit-cost arithmetic and dictionary access, topological ordering and scalar recurrence evaluation take \(O(V+E)\) operations. Each edge participates in ordering and one candidate comparison. Values, one backpointer per state, ordering, and degree counts require \(O(V)\) auxiliary entries. The reachable adjacency lists require \(O(V+E)\) entries. Constructing and validating a larger supplied graph also inspects and stores its unreachable input states and edges; the solver bound refers to its reachable subgraph.

These are abstract counts. Python dictionaries and objects have overhead; exact rational additions can increase numerator and denominator lengths. Neither hashing arbitrary state descriptions nor exact arithmetic is universally constant-time. The program's finite cost/graph bounds and algorithmic checks do not constitute a hardware memory or timing benchmark.

The official dynamic-programming implementation caches a whole solution suffix for each state, rather than only its scalar value and one edge. On a chain of \(V\) states ending in a goal, those suffix lists contain \(V-1,V-2,\ldots,1,0\) step references. The total is

\[\sum_{j=0}^{V-1}j=\frac{V(V-1)}2.\]

Creating a new list by prepending an edge to an existing suffix copies those references; summing a full suffix's costs traverses it again. On this chain the representation therefore introduces quadratic list storage and work, even though the mathematical scalar recurrence is linear. Memoizing a richer object can be useful, but it does not inherit the scalar implementation's cost bound automatically.

State sufficiency also controls space. With destination \(n\), at most \(K\) tickets initially, and the last-action bit, the candidate state grid contains at most \(2n(K+1)\) combinations. Many are unreachable; the program constructs only reachable combinations. Additional binary resources can multiply the grid again. Caching removes repeated histories only after paying for the distinct future situations the model retains.

A raw token-prefix state usually has very little exact merging: different ordered prefixes are different states. Merging them by length alone would be efficient but wrong whenever their next-token distributions or terminal validity differ. The computational attraction of approximate search comes partly from this absence of cheap sufficient-state compression.

9. Sampling succeeds only on complete paths inside its support 50:04

A stochastic policy \(\pi(a\mid s)\) assigns probabilities to legal actions at nonterminal state \(s\), with nonnegative values summing to one. A rollout samples successive actions from that policy until it reaches a goal, encounters a dead end, or exhausts a horizon \(H\). Only the first outcome is a complete candidate.

Best of \(N_{\mathrm{sample}}\) runs that many rollouts and returns the cheapest complete one, where \(N_{\mathrm{sample}}\) is a positive integer trial budget. If all fail, it returns failure. A partial route with cost zero must never defeat a successful complete route simply because its prefix cost is smaller.

Let \(q\) be the probability that one rollout completes some optimal path within \(H\). Assuming independent trials with the same fixed policy and horizon, each trial misses with probability \(1-q\). Multiplying the independent miss events gives

\[\Pr(\text{all trials miss})=(1-q)^{N_{\mathrm{sample}}},\qquad \Pr(\text{at least one optimum})=1-(1-q)^{N_{\mathrm{sample}}}.\]

If \(q=0\), extra trials cannot help. This can happen because the horizon is too short or because the policy excludes a necessary action. If \(q=1\), one trial succeeds with probability one. For \(0\lt q\lt1\), the miss probability tends to zero as the trial budget grows without bound, but finite budgets can still be ineffective. In this latter domain, for a desired miss probability at most \(\varepsilon\in(0,1)\), taking logs and dividing by the negative number \(\log(1-q)\) gives

\[N_{\mathrm{sample}}\ge\left\lceil\frac{\log\varepsilon}{\log(1-q)}\right\rceil.\]

Here logs are natural and the ceiling chooses an integer trial count. For \(q=2^{-20}\), 1000 trials still miss with probability about 0.99904678. Reducing the miss probability to 0.01 requires 4,828,869 trials under these assumptions. A policy can improve efficiency by allocating more mass to useful paths, but a deterministic policy concentrated on the wrong path removes support entirely.

Independence is consequential. If all trials reuse a single random choice and follow the same resulting path, their collective miss probability is \(1-q\), regardless of the nominal trial count. The seeded pseudorandom program produces a reproducible finite trace; its observed success does not establish an independent-trial model for a real generator.

Parallel rollouts can reduce elapsed time when compute and communication permit, but do not change the mathematical candidate set or trial budget. A final minimum over complete costs is order-independent; tie-selected routes can depend on reduction order unless tie rules are standardized. We report finite visits and costs here, not a parallel speedup.

10. Beam search pays for fewer prefixes by making irreversible choices 58:05

Beam search maintains a bounded collection of path records. Fix a positive integer width \(B\) and a finite action horizon \(H\). Our depth-synchronous variant starts with the empty-action path. At each round it keeps already complete records, extends every unfinished record by every legal edge, sorts the resulting pool by accumulated cost, and retains its first \(B\) records. After at most \(H\) rounds, it chooses the cheapest retained complete record.

Ties retain candidate enumeration order through a stable sort. Complete records occupy beam slots in subsequent rounds; they are not separately archived. Dead ends produce no extensions. A start-goal path succeeds immediately. An empty final set of complete candidates returns failure. These conventions are part of the algorithm, not incidental formatting.

Take the graph with start edges \(s\to a\) costing 1 and \(s\to b\) costing 2. Let \(a\to g\) cost 100 and \(b\to g\) cost 0. With \(H=2\), width 1 retains \(a\) after the first round and returns total cost 101. Width 2 retains both prefixes and returns cost 2. The locally cheaper prefix leads to the worse complete route.

Width 1 is greedy under this prefix-cost ranking. It is not a general best-first procedure that globally prioritizes states using a future-cost estimate. Beam search's ranking can be replaced with other heuristics, but those define different algorithms and require separate assumptions. Accumulated cost alone contains no estimate of the remaining suffix.

If each retained nonterminal record has at most \(b\) children, the candidate pool has at most \(B\max\{1,b\}\) records per round. Comparison sorting therefore costs at most order \(H B\max\{1,b\}\log(B\max\{1,b\})\) ranking operations under a unit-cost comparison model, with the usual constant-size treatment when the pool is at most one. Full immutable path copying adds up to another factor proportional to path length. A width bound is not a bound on model evaluations, token memory, or elapsed time without these details.

11. A wider beam need not contain the narrower beam's answer 1:07:16

It is tempting to infer that increasing width always improves the final result. That would follow if the larger run retained every candidate from the smaller run at every depth. Standard independently run beams do not satisfy that nesting property. Newly admitted parents can generate enough cheaply ranked children to displace the smaller run's surviving branch.

With horizon 3 and width 1, the first round keeps \(a\) at cost 1. Its children have accumulated costs 5 and 5.5, so the second round keeps \(a1\). The final answer costs 5. Width 2 initially keeps both \(a\) and \(b\). At the second round, \(b1,b2\) each cost 2 and crowd out both \(a\)-branch children. The final answer costs 102. The wider run is worse despite having more candidates and no negative edges.

Without pruning, a depth-synchronous expansion with finite horizon enumerates every path of at most that many actions, keeping complete paths available at later rounds. On a finite branching graph there is a finite width large enough to avoid every truncation through that horizon. The resulting answer is optimal within the horizon. An unbounded-width slogan does not remove a finite horizon, guarantee termination on unbounded cyclic paths, or prove monotonicity between finite-width runs.

Holding completed records inside the beam favors some short solutions by letting them compete against unfinished prefixes. Archiving complete incumbents separately changes this behavior. Prefix-cost pruning against an incumbent also needs a valid lower bound: with nonnegative future costs, a prefix already more expensive than the incumbent cannot improve it. With an edge cost 10 followed by a cost−20 edge, a prefix of 10 can finish at−10 and beat an incumbent of 0. Pruning that prefix solely on its current cost is unsound.

These distinctions matter for terminal rewards in language-model search. A negative reward edge can make an expensive unfinished prefix eventually attractive. They also limit the recording's analogy to particle filtering: a deterministic cost-sorted beam is not a probabilistic particle approximation unless the proposal, weights, and resampling distribution are separately defined. We do not transfer particle-filter guarantees to this algorithm.

12. Token search connects likelihood to path cost, not automatically to truth 1:11:19

Fix a language model, a prompt represented by ordered token IDs \(u\), and a finite vocabulary \(\mathcal V\) containing an explicit end-of-sequence token, EOS. A state is the prompt plus an ordered generated token-ID prefix. At action position \(t\), the model assigns normalized conditional probabilities \(p_t(a\mid u,y_{1:t-1})\) to vocabulary tokens. Here \(y_{1:t-1}\) is the generated prefix, and candidate \(y_{1:L}\) includes EOS at its final position.

For a candidate whose every conditional probability is positive, the chain rule and additivity of the natural log give

\[p(y_{1:L}\mid u)=\prod_{t=1}^L p_t(y_t\mid u,y_{1:t-1}),\qquad -\log p(y_{1:L}\mid u)=\sum_{t=1}^L-\log p_t(y_t\mid u,y_{1:t-1}).\]

Thus minimizing summed surprisal, measured in nats, maximizes the modeled sequence probability. A zero-probability edge has infinite surprisal and is outside a finite-cost candidate's support. The prompt's own likelihood is excluded because the prompt is conditioned on, and EOS is included because termination is part of the candidate event. Comparing variable lengths by summed surprisal can favor shorter sequences; dividing by length defines a different objective.

High model probability is not equivalent to correctness. Define a hard verifier \(v(y)\in\{0,1\}\) and restrict goals to completed candidates for which \(v(y)=1\). A solver can then minimize likelihood cost over that feasible set. Its conclusion remains “best according to this model among candidates accepted by this verifier.” Verifier acceptance must still be compared with the actual task's correctness criterion.

Brown and colleagues' 2024 Large Language Monkeys, v1 separates generation coverage from selecting a correct answer (Figure 1, page 2). In its reported Llama-3-8B-Instruct/MATH setup, coverage rises from 79.8% at 100 attempts to 95.3% at 10,000. Common selection methods, including majority voting and reward-model scoring, plateau; its page 3 summary reports selection accuracy changing from 38.7% to 39.8% over those budgets. Figure 7, page 10, shows this oracle-versus-selection gap. These are dated experimental results for that setup, not a guarantee for arbitrary prompts or present models.

The paper's page 4 reports a finite-pool pass-at-\(k\) estimator. We can derive its combinatorial quantity without confusing it with the independent-trial formula. Suppose a retained pool contains \(N_{\mathrm{pool}}\) candidates, exactly \(C_{\mathrm{pool}}\) of which meet a stipulated correctness label. Choose \(k\) distinct pool members uniformly without replacement. There are \(\binom{N_{\mathrm{pool}}}{k}\) equally likely subsets and \(\binom{N_{\mathrm{pool}}-C_{\mathrm{pool}}}{k}\) all-incorrect subsets. Therefore

\[\Pr(\text{chosen subset contains a correct candidate}\mid\text{this pool})=1-\frac{\binom{N_{\mathrm{pool}}-C_{\mathrm{pool}}}{k}}{\binom{N_{\mathrm{pool}}}{k}}.\]

Define \(\binom{m}{k}=0\) when \(k\gt m\). The domain is \(1\le k\le N_{\mathrm{pool}}\) and \(0\le C_{\mathrm{pool}}\le N_{\mathrm{pool}}\). For a pool of 5 with 2 correct candidates, choosing 2 has coverage \(1-3/10=0.7\). Treating the observed fraction 0.4 as a fresh independent-trial probability gives 0.64 instead. One conditions on a fixed pool without replacement; the other posits future draws with replacement. Neither supplies a selector that recognizes the correct member.

A simple original distribution makes the gap explicit. If an independently drawn answer is correct with probability 0.01 and all incorrect answers agree on one wrong value, oracle coverage reaches about 0.634 after 100 draws and 0.999957 after 1000. A majority selector still tends toward the wrong answer because the wrong value has probability 0.99. Candidate generation and answer selection require separate evidence.

13. Check the transition, support, reward, and terminal test in the actual demo 1:15:13

The pinned language-model demonstration illustrates token search, but its executable contracts differ from an exact token-prefix model. It keeps a text string, decodes one proposed token, appends that text, then tokenizes the whole string again on the next call. Decoding and re-tokenizing need not preserve the previously generated token-ID prefix. A clean token search model should retain ordered IDs directly and decode only for display or a specified verifier.

The demo offers only the five highest-probability next tokens at each state. This removes other model-supported actions from search. If a necessary token falls outside that set, increasing the beam or number of rollouts cannot recover the excluded path. One can expand the action set, but the resulting compute and support are different.

Its terminal predicate checks whether text ends with a closing parenthesis. Its bonus predicate calls Python eval and accepts any expression that evaluates without raising an exception. That does not establish JSON syntax, a numeric return value, the intended arithmetic answer, or valid intermediate reasoning. The original function is not used by our program. Our safe fixture parses JSON data only and verifies an exact declared answer schema.

The demo also subtracts 100 from an accepted terminating edge's cost. If \(R\gt0\) is a finite terminal bonus and \(C_{\mathrm{LM}}(y)\) is the base summed surprisal, its shaped complete score is

\[C_R(y)=C_{\mathrm{LM}}(y)-R\,v(y).\]

This is a soft preference, not a hard feasibility constraint. With \(R=100\), a valid candidate of base cost 200 has shaped cost 100 and loses to an invalid candidate of base cost 1. No fixed finite bonus guarantees acceptance without an appropriate bound on competing likelihood costs. The negative bonus edge also invalidates nonnegative-prefix pruning.

The demo's sampling policy applies softmax to the negative shaped successor costs. For retained action set \(\mathcal T(s)\), base action probability \(p(a\mid s)\), and immediate bonus indicator \(v_a\), elementary substitution gives

\[\widetilde\pi(a\mid s)=\frac{p(a\mid s)e^{Rv_a}}{\sum_{b\in\mathcal T(s)}p(b\mid s)e^{Rv_b}},\qquad a\in\mathcal T(s).\]

The symbol \(b\) indexes an alternative action in this denominator. This is neither the untruncated model policy nor, when bonuses differ, that policy simply conditioned on its top-five support. For base probabilities 2/3 and 1/3 with a bonus 100 on the first action only, the shaped probability is \(1/(1+e^{-100}/2)\), extremely close to 1. Binary64 arithmetic rounds this example to 1, although its exact real value is strictly less than 1. The source code's model identifier is a demonstration setting, not evidence of current model quality or an experiment run here.

For the program's stipulated arithmetic task, the correct answer to \(3+7\cdot3\) is 24 under ordinary multiplication precedence. The hard predicate accepts a JSON object with exactly one key, answer, whose value has exact integer type and equals 24. Duplicate keys, Boolean values, floating-point 24.0, extra keys, incorrect integers, and malformed JSON are rejected. Parsing data instead of executing expressions removes the demo's execution behavior, but this predicate certifies only this exact answer format and value. It is not a general verifier for reasoning, tools, or arbitrary arithmetic.

Counting a failed prefix as a successful cheap answer corrupts the experiment before any statistical comparison begins.

Increasing compute can explore a better part of an unchanged feasible set. It cannot include an action deleted from support, restore a discarded resource variable, or turn a proxy reward into task truth. Learned proposal quality, objective alignment, and search efficiency are separate contributions. The next search chapter develops algorithms for cyclic graphs and estimated remaining costs; their conditions should not be inferred from this chapter's acyclic proof.

def integer(value, name, low, high):

def name(value, label):

@dataclass(frozen=True)
class Edge:
    action: str
    target: str
    cost: Fraction


class Problem:
    "Validated snapshot: dict[str, sequence[Edge]], start, iterable of goals."

    __slots__ = ("graph", "start", "goals")

    def __init__(self, graph, start, goals):
        if type(graph) is not dict or not 1 <= len(graph) <= 10000:
            raise ValueError("graph must be a dict with1..10000 states")
        nodes = {name(s, "state") for s in graph}
        start = name(start, "start")
        if start not in nodes or type(goals) not in (
            tuple,
            list,
            set,
            frozenset,
        ):
            raise ValueError(
                "start must be a state; goals must be a finite collection"
            )
        frozen_goals = frozenset(name(g, "goal") for g in goals)
        if not frozen_goals <= nodes:
            raise ValueError("goals must be graph states")
        copied = {}
        count = 0
        for state, edges in graph.items():
            if type(edges) not in (tuple, list):
                raise ValueError("adjacency must be tuple or list")
            actions = set()
            row = []
            for edge in edges:
                if type(edge) is not Edge:
                    raise ValueError("adjacency entries must be Edge objects")
                action, target = (
                    name(edge.action, "action"),
                    name(edge.target, "target"),
                )
                if action in actions or target not in nodes:
                    raise ValueError(
                        (
                            (
                                'actions must be unique per state; '
                                'targets must exist'
                            )
                        )
                    )
                if type(edge.cost) not in (int, Fraction):
                    raise ValueError(
                        "cost must be an integer or Fraction, excluding bool"
                    )
                cost = Fraction(edge.cost)
                if abs(cost) > 1000000 or cost.denominator > 1000000:
                    raise ValueError(
                        (
                            (
                                'cost magnitude and denominator '
                                'must be at most1000000'
                            )
                        )
                    )
                row.append(Edge(action, target, cost))
                actions.add(action)
                count += 1
                if count > 100000:
                    raise ValueError("at most100000 edges supported")
            copied[state] = tuple(row)
        object.__setattr__(self, "graph", MappingProxyType(copied))
        object.__setattr__(self, "start", start)
        object.__setattr__(self, "goals", frozen_goals)

    def __setattr__(self, key, value):
        raise AttributeError("Problem is immutable")


@dataclass(frozen=True)
class Solution:
    states: tuple
    actions: tuple
    cost: Fraction


def problem(value):
    if type(value) is not Problem:
        raise ValueError("a validated Problem is required")
    return value


def outgoing(p, state):
    return () if state in p.goals else p.graph[state]


def travel(n, tickets=None, forbid_consecutive=False):
    integer(n, "n", 1, 200)
    if tickets is not None:
        integer(tickets, "tickets", 0, 20)
    if type(forbid_consecutive) is not bool:
        raise ValueError("forbid_consecutive must be bool")

    def key(state):
        i, k, last = state
        return f"{i}|{k if k is not None else 'u'}|{int(last)}"

    start = (1, tickets, False)
    pending, seen, graph, goals = deque([start]), {start}, {}, []
    while pending:
        state = pending.popleft()
        i, k, last = state
        successors = []
        if i == n:
            goals.append(key(state))
        else:
            successors.append(("walk", (i + 1, k, False), 1))
            if 2 * i <= n and (k is None or k > 0) and not last:
                successors.append(
                    (
                        ("tram"),
                        (
                            2 * i,
                            None if k is None else k - 1,
                            forbid_consecutive,
                        ),
                        2,
                    )
                )
        graph[key(state)] = [Edge(a, key(t), c) for a, t, c in successors]
        for _, target, _ in successors:
            if target not in seen:
                seen.add(target)
                pending.append(target)
    return Problem(graph, key(start), goals)


def dag_order(p):
    "Topological order of start-reachable states, goals treated as absorbing."
    problem(p)
    reachable, discovered, stack = {p.start}, [], [p.start]
    while stack:
        state = stack.pop()
        discovered.append(state)
        for edge in outgoing(p, state):
            if edge.target not in reachable:
                reachable.add(edge.target)
                stack.append(edge.target)
    indegree = {s: 0 for s in discovered}
    for state in indegree:
        for edge in outgoing(p, state):
            indegree[edge.target] += 1
    ready = deque(s for s, degree in indegree.items() if degree == 0)
    order = []
    while ready:
        state = ready.popleft()
        order.append(state)
        for edge in outgoing(p, state):
            indegree[edge.target] -= 1
            if indegree[edge.target] == 0:
                ready.append(edge.target)
    if len(order) != len(reachable):
        raise ValueError(
            "DAG solver requires acyclic start-reachable nonterminal graph"
        )
    return order


def exact_dag(p):
    order = dag_order(p)
    values, choices = {}, {}
    for state in reversed(order):
        best, choice = (
            (Fraction(0), None) if state in p.goals else (None, None)
        )
        for edge in outgoing(p, state):
            suffix = values[edge.target]
            if suffix is not None:
                candidate = edge.cost + suffix
                if best is None or candidate < best:
                    best, choice = candidate, edge
        values[state], choices[state] = best, choice
    if values[p.start] is None:
        return None, values
    states, actions, state = [p.start], [], p.start
    while state not in p.goals:
        edge = choices[state]
        actions.append(edge.action)
        state = edge.target
        states.append(state)
    return Solution(tuple(states), tuple(actions), values[p.start]), values


def exhaustive(p, max_visits=100000):
    dag_order(p)
    integer(max_visits, "max_visits", 1, 1000000)
    stack = [Solution((p.start,), (), Fraction(0))]
    best, visits = None, 0
    while stack:
        path = stack.pop()
        visits += 1
        if visits > max_visits:
            raise ValueError("exhaustive visit budget exceeded")
        state = path.states[-1]
        if state in p.goals:
            if best is None or path.cost < best.cost:
                best = path
        else:
            for edge in reversed(outgoing(p, state)):
                stack.append(
                    Solution(
                        path.states + (edge.target,),
                        path.actions + (edge.action,),
                        path.cost + edge.cost,
                    )
                )
    return best, visits


def beam(p, width, horizon):
    problem(p)
    integer(width, "width", 1, 10000)
    integer(horizon, "horizon", 0, 1000)
    candidates = [Solution((p.start,), (), Fraction(0))]
    for _ in range(horizon):
        pool = []
        for path in candidates:
            state = path.states[-1]
            if state in p.goals:
                pool.append(path)
            else:
                pool.extend(
                    Solution(
                        path.states + (e.target,),
                        path.actions + (e.action,),
                        path.cost + e.cost,
                    )
                    for e in outgoing(p, state)
                )
            if len(pool) > 200000:
                raise ValueError("beam candidate budget exceeded")
        candidates = sorted(pool, key=lambda path: path.cost)[:width]
        if not candidates or all(
            path.states[-1] in p.goals for path in candidates
        ):
            break
    complete = [path for path in candidates if path.states[-1] in p.goals]
    return min(complete, key=lambda path: path.cost, default=None)


def best_sample(p, trials, horizon, seed=0):
    problem(p)
    integer(trials, "trials", 1, 10000)
    integer(horizon, "horizon", 0, 1000)
    integer(seed, "seed", -(2**63), 2**63 - 1)
    if trials * max(horizon, 1) > 100000:
        raise ValueError("sampling action budget exceeded")
    rng, best, completed = Random(seed), None, 0
    for _ in range(trials):
        states, actions, cost, state = [p.start], [], Fraction(0), p.start
        for _ in range(horizon):
            if state in p.goals:
                break
            edges = outgoing(p, state)
            if not edges:
                break
            edge = rng.choice(edges)
            actions.append(edge.action)
            cost += edge.cost
            state = edge.target
            states.append(state)
        if state in p.goals:
            completed += 1
            candidate = Solution(tuple(states), tuple(actions), cost)
            if best is None or cost < best.cost:
                best = candidate
    return best, completed


def pass_at_k(total, correct, k):
    integer(total, "total", 1, 100000)
    integer(correct, "correct", 0, total)
    integer(k, "k", 1, total)
    return 1 - Fraction(comb(total - correct, k), comb(total, k))

16. Six worked problems that distinguish the guarantees

1. When may two histories share a cached future?

Destination 10 has one remaining ticket, no consecutive trams, and the state rules above. Compute the future costs at location 5 with previous-action bits 0 and 1. A programmer caches only by (location,tickets); explain why this fails. Prove a sufficient history-equivalence condition for caching under the finite-horizon model, and give one additional variable required if edge costs depend on departure time.

Complete solution

At \((5,1,0)\), tram 5→10 is legal and costs 2. Walking instead cannot be cheaper than 2 because at least two positive-cost actions would be required and the only direct goal edge is the tram; in fact, after walking to 6 no tram stays within 10, so that route costs 5. Thus the optimum is 2.

At \((5,1,1)\), the tram is initially forbidden. The mandatory walk to 6 resets the bit, but every possible tram from 6 or later overshoots 10. Five walks cost 5. The two histories have different futures despite identical (location,tickets), so whichever value is cached first is wrong for the other query.

A sufficient condition is equality of terminal status and equality of legal action labels, incremental costs, and compressed successor states for every corresponding action. At zero remaining horizon, equivalent states agree on the goal-zero versus unreachable-infinity value. Assuming equality of successor values for remaining horizon \(h-1\), the same candidate costs yield the same minimum at horizon \(h\). Induction proves equal horizon-bounded futures. Earlier prefix cost is not part of the suffix state under an additive objective.

Departure-time dependence requires a clock coordinate or a sufficient time class, such as a timetable slot if costs genuinely depend only on that slot. Adding an arbitrary rounded time can still be invalid if two rounded values imply different future costs. State compression must preserve the actual stipulated transition/cost functions.

2. Prove the recurrence without assuming nonnegative edges

A DAG has start edges s→a with cost 3 and s→d with cost −100. State a has an edge to terminal g with cost −5; state d is a nonterminal dead end. Compute all future values and the complete optimum. Prove why the cheaper-looking first edge to d cannot win. Then replace the dead end with a self-loop of cost −1 and an edge to g of cost 0; explain how the unrestricted and finite-horizon problems differ.

Complete solution

Goal \(g\) has value 0. Dead end \(d\) has value \(+\infty\). State \(a\) has value−5. The start candidates are \(3-5=-2\) and \(-100+\infty=+\infty\), so the complete optimum is−2 along s→a→g.

Every complete path starts with one legal first edge, and its suffix must itself reach a goal. The reverse-order induction establishes the minimum suffix cost for each successor. A dead-end prefix contributes no feasible complete path, irrespective of its prefix score. This first-edge argument proves both the lower bound and attainment by concatenating a chosen edge with an attained finite suffix; nonnegative costs were never needed.

After replacing the dead end, the path s→d, followed by \(m\) self-loops, then d→g has cost \(-100-m\) for every nonnegative integer \(m\). The unrestricted infimum is \(-\infty\), with no finite minimizing path. The DAG solver correctly rejects this reachable cycle.

Under a horizon \(H\ge2\), the branch throughd permits at most \(H-2\) loops, so its best cost is \(-100-(H-2)=-H-98\). It beats−2. For \(H\lt2\), neither route completes. Finite horizon gives a finite, explicitly different optimization problem.

3. Explain a speedup without claiming a memory measurement

Build a start followed by h≥1 layers of two states, with full connections between successive layers and both last-layer states terminal. Count distinct states, complete paths, and depth-first entered prefixes. Explain why scalar dynamic programming avoids repeated work. On a separate V-state chain, compute the total cached suffix-list step references and compare with scalar values/backpointers.

Complete solution

The graph has \(1+2h\) states. Every action position chooses one of two next-layer states, so each of the \(h\) positions has two choices and there are \(2^h\) complete histories. At depth \(t\) the unfolded traversal has \(2^t\) prefixes. Summing depths 0 through \(h\) gives \(2^{h+1}-1\) visits. The edge count is 2 for the first layer plus 4 for each later transition, or \(4h-2\).

Scalar dynamic programming evaluates each sufficient state once and scans each edge once, so its abstract work is linear in this graph's state/edge count, hence linear in h. It does not enumerate the \(2^h\) histories. A stored backpointer at a state can reconstruct one minimizing suffix reused after any prefix reaching that state.

On a V-state chain, complete suffixes have lengths 0 through \(V-1\). Storing a separate list for each state uses \(V(V-1)/2\) step references; for \(V=100\) this is 4950. Scalar values and one next-edge reference per nonterminal use only \(O(V)\) entries, followed by one output route of length \(V-1\). The suffix lists might share step objects while still copying list slots. References, objects, rational digit lengths, and bytes are different units. No actual byte count follows without a representation measurement.

4. Diagnose a sampling budget and its hidden assumptions

An independent rollout reaches an optimal complete path with probability q=2^−20. Compute the miss probability after 1000 trials and the smallest integer budget making it at most 0.01. Explain what changes if all trials share a single random draw, if the horizon excludes every optimal path, or if a fixed five-candidate pool contains two correct candidates and two distinct candidates are selected uniformly.

Complete solution

Independence and identical per-trial success probability give \((1-2^{-20})^{1000}\approx0.9990467798321046\). The smallest budget is the ceiling of \(\log(0.01)/\log(1-2^{-20})\), namely 4,828,869. A high-precision numerical check gives a miss probability about 0.00999999647481 at that budget and 0.01000000601156 one trial earlier, confirming the neighboring boundary rather than merely rounding the quotient.

Perfectly correlated repetition has collective miss probability \(1-q\). The nominal trial count cannot be inserted into the exponent. A horizon that excludes all optimal completions makes the relevant \(q\) zero, so the denominator \(\log(1-q)\) vanishes and no finite or infinite number of those truncated trials recovers the excluded optimum. Changing the horizon changes the per-trial event and probability.

For the fixed pool, ten pairs are equally likely. Three pairs consist entirely of the three incorrect candidates, leaving seven pairs with at least one correct member. The conditional coverage is 7/10. Fresh independent draws with probability 2/5 would instead yield \(1-(3/5)^2=16/25\). Even 7/10 coverage assumes an oracle can label the pool for analysis; it does not tell a deployed selector which candidate is correct.

5. Trace a beam rather than assuming width monotonicity

Use the nonnegative-cost graph in Section 11 with horizon 3, stable ties, and complete candidates held inside the beam. Trace widths 1 and 2, giving every retained path's accumulated cost after each round. Is width 2 guaranteed to improve width 1? Would increasing the horizon alone recover the lost branch?

Complete solution

Width 1 begins with s at 0. Round 1 compares s→a at 1 and s→b at 2, retaining s→a. Round 2 compares s→a→a1 at 5 with s→a→a2 at 5.5, retaining the first. Round 3 completes s→a→a1→g at 5. That is its answer.

Width 2 retains s→a at 1 and s→b at 2 in round 1. The round 2 pool contains a1 at 5, a2 at 5.5, b1 at 2, and b2 at 2. Sorting retains the two b-paths; both a-paths are discarded. Round 3 completes both retained b-paths at 102. Stable enumeration picks the b1 route in their tie, but either costs 102.

Width 2 is worse, so no universal width-monotonicity claim follows. The two runs' depth 2 beams are not nested. A larger horizon cannot reconstruct the lost a-branch because neither retained b-state has an edge back to it, and all retained records are complete by round 3. After that, holding completed records leaves the answer 102. A modified archive, restart strategy, or ranking defines another algorithm requiring its own analysis.

6. Repair a likelihood objective and a verifier separately

A search subtracts \(R=100\) for an accepted terminal response. Candidate A passes the proxy and has base surprisal 200; candidate B fails it and has base surprisal 1. Determine the selected candidate. A local two-action policy has base probabilities 2/3 and 1/3 and awards the same bonus only to the first action; derive its shaped probability. Finally design a safe verifier and an evaluation protocol for the stipulated arithmetic answer 24 without claiming general reasoning correctness.

Complete solution

Shaped costs are 100 for A and 1 for B, so minimization chooses B. A finite soft bonus cannot enforce a hard acceptance requirement here. To require a passing answer, define only passing completed responses as feasible goals and report failure when no supported completion passes. This repairs objective feasibility; it does not prove the proxy corresponds to task truth.

Exponentiating negative shaped costs gives unnormalized weights \((2/3)e^{100}\) and \(1/3\). Normalizing the first gives \(2e^{100}/(2e^{100}+1)=1/(1+e^{-100}/2)\). It differs from 2/3 and is strictly below 1 in real arithmetic, despite rounding to 1 in binary64. Truncating a larger vocabulary to these two actions would additionally condition support before the bonus reweighting.

For this task, parse data as JSON; require exactly the key answer, reject duplicate keys, require exact integer type, and compare with 24. Rejecting Boolean values matters because Python's Boolean type is a subtype of integer. Do not execute the candidate. Test correct 24, incorrect 23, 24.0, true, a string 24, duplicate/extra keys, malformed data, and a string containing code.
