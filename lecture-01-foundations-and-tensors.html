Intelligent agents, historical ideas, and executable tensors

A capable agent must choose a useful action from incomplete information, within a finite budget. Tensor programming makes that decision executable at scale—but a fast, shape-correct program can still implement the wrong objective.

Independent enhanced chapter accompanying Percy Liang's introductory recording. The topic sequence and timestamps follow locally generated speech recognition. The delivery-robot case, derivations, numerical examples, code, and exercises are original teaching constructions. Captions establish timing; primary sources establish technical notation and implementation semantics.

1. A robot must decide before the corridor changes 02:18

A delivery robot approaches a corridor where a cart partly obscures the view. Its camera suggests that the corridor may be blocked. Going forward saves time if the path is clear; waiting avoids a collision but delays the delivery. A fluent explanation of this situation is insufficient. The system must turn evidence into an action, and it must finish before its observation becomes stale.

An agent is a system that receives observations and chooses actions affecting an environment. Let \(t=0,1,\ldots\) index decision times. The environment has a state \(s_t\), such as the positions of people and obstacles. The robot receives an observation \(o_t\), such as a camera image. Its history \(h_t=(o_0,a_0,o_1,\ldots,a_{t-1},o_t)\) contains the observations and earlier actions available at time \(t\). A policy \(\pi\) maps that history to an action \(a_t=\pi(h_t)\), here either go or wait. The true state generally contains information absent from the history.

Perception constructs a useful representation from observations. Reasoning uses that representation and a model to compare possible consequences. Action commits the chosen alternative to the environment. Learning changes some part of the system using experience. These are functional roles rather than four isolated software services: a learned network may implement perception and action selection together, while a planner uses the network's predictions.

For our first decision, compress the history into a number \(p=P(\text{blocked}\mid h_t)\), the probability of blockage conditional on available evidence. This is a deliberately small belief state: a representation of uncertainty about the world. Later chapters will examine when such a compressed representation retains the information needed for future decisions. Here we assume the single number suffices for the immediate choice.

Derive the action rule before implementing it

Let a loss be a numerical penalty, measured in stipulated decision units. Going costs one unit when clear and eleven when blocked. Waiting costs three units in either state. These are teaching values, not a real collision-risk policy. Expected loss averages the possible penalties using their probabilities:

\[L_{\rm go}(p)=(1-p)\cdot1+p\cdot11=1+10p,\qquad L_{\rm wait}(p)=3.\]

Go is preferred exactly when \(1+10p\lt3\), or \(p\lt0.2\). Define our tie rule to wait at \(p=0.2\). A belief of 0.1 gives expected go loss 2 and favors movement. A belief of 0.4 gives expected go loss 5 and favors waiting. The computation is optimal only for this belief, loss table, and one-step action set. It does not establish that the robot is safe or that its estimated probability is accurate.

A sharper camera may change \(p\); a better planner may compare more actions; a learning procedure may improve the mapping from observations to \(p\). Faster hardware may reduce decision latency without changing any of these objects. Keeping those changes separate lets us diagnose failures. A collision after choosing go can result from a bad observation model, a bad loss table, an incomplete action set, or unlucky realization of an honestly represented risk.

Computation and information impose different limits. Suppose a clear corridor and a blocked corridor produce exactly the same observation history \(h_t\). A deterministic policy that receives only that history must return the same action in both states, so more calculation alone cannot guarantee distinguishing them. An additional observation or a justified model assumption can break that ambiguity. Conversely, even an accurate map does not solve the execution problem if searching it takes longer than the available budget. The robot needs both an information model and an execution budget; an optimality claim must specify those constraints.

2. Objectives, measurement, and executable understanding 07:46

Choosing a loss function is already a substantive design decision. If the blocked-path penalty is increased from eleven to thirty-one, go has loss \(1+30p\), and the threshold becomes \(p\lt2/30=1/15\). An unchanged perception model now produces different actions. Optimizing more accurately cannot decide which penalty is appropriate; that choice expresses priorities outside the optimizer.

The lecture distinguishes developer intent from wider social effects. A developer might reward fast deliveries, while pedestrians value clear passage and workers value predictable behavior. These outcomes should initially remain separate measurements: delivery time, obstruction frequency, near misses, and injury risk. A weighted total combines them only after a decision-maker explicitly supplies weights. The arithmetic does not justify those weights.

Alignment, in this chapter's limited operational sense, asks whether the agent's behavior realizes the intended objectives. A robot that minimizes logged delivery time by ending its timer before reaching the destination exploits a measurement error. A robot that genuinely minimizes delivery time while obstructing a public corridor exposes an incomplete objective. Both demand specification work, but they are different failures.

The course's tensor-native approach connects reasoning to executable objects. A tensor can encode observations, transition probabilities, candidate-action losses, or trainable parameters. The operation that averages losses over uncertain states will eventually be a contraction of arrays. A computation written this way becomes amenable to testing, batching, and efficient numerical libraries without losing its interpretation.

Executable lectures also make intermediate states inspectable. Yet executable precision is narrower than semantic correctness. A program can unambiguously add a cost vector along the wrong axis. It can return a plausible number for an ill-defined objective. Our discipline is therefore to specify what each axis and number means, derive the operation, and only then check that the program implements it.

In this chapter, prerequisite linear algebra includes vectors, matrices, and finite sums. We will develop array rank, shape, broadcasting, and contraction explicitly. The running policy remains the go-or-wait rule. Tensors will allow many robots and many observation times to use that same rule without confusing independent examples with interacting parts of one example.

3. Three traditions contribute different parts of the agent 17:29

Turing's 1950 Computing Machinery and Intelligence reframed a broad question about thinking through an observable imitation game. The enduring methodological move is to specify evidence that could discriminate systems. Passing a conversational test does not certify our robot's collision avoidance: a measurement answers the question its protocol actually poses.

Symbols make structure explicit, but search and knowledge are costly

Symbolic AI represents objects, relations, and rules explicitly. A corridor map can be a graph, with locations as nodes and traversable connections as edges. A rule can prohibit entering an occupied location. A search algorithm then explores sequences of actions compatible with those rules. The 1955 Dartmouth proposal for the 1956 summer project documents the ambitious early program connecting language, abstraction, and machine intelligence.

Early game playing and theorem proving showed that formal descriptions could support nontrivial reasoning. They did not remove resource limits. If each decision has \(b\) alternatives and a plan contains \(d\) decisions, a full tree has \(b^d\) leaves. For \(b=4\) and \(d=10\), there are 1,048,576 leaves; adding one level multiplies that number by four. This original calculation illustrates why a compact set of rules need not imply a cheap search.

Expert systems attempted to make domain knowledge explicit in specialist rules. Knowledge can reduce search by excluding irrelevant possibilities. It can also become difficult to acquire and maintain, particularly when exceptions interact and observations are uncertain. For our robot, “never enter an occupied corridor” is clear only after defining occupancy, observation uncertainty, and what happens when every route appears occupied.

The lecture links disappointed expectations to periods of reduced AI enthusiasm and funding. It also labels its famous machine-translation anecdote as folklore. We preserve the substantive lesson—limited knowledge and computation constrain systems—without promoting that anecdote or a single-cause account of an “AI winter” into historical evidence. Useful programming ideas emerged even when ambitious intelligence claims outran results.

Neural models learn representations; statistical methods discipline inference

Neural AI builds functions by composing parameterized transformations. A parameter is a stored numerical value adjusted during learning. The robot's pixels can be transformed into obstacle-related features and then into a blockage estimate. McCulloch and Pitts's 1943 logical model of nervous activity already connected neuron-like units to logical computation; symbolic and neural ideas were never completely separate.

A perceptron makes a binary decision from a weighted sum of inputs and a threshold. Its representational limitation is easy to expose: no single linear boundary separates the two positive corners of exclusive-or from the two negative corners. The issue is not insufficient training time; the required classifier is absent from the model family. Adding nonlinear intermediate representations changes that family. The exercise below proves this small impossibility directly.

Learning a multilayer representation requires assigning credit through a composition of functions. Rumelhart, Hinton, and Williams's 1986 paper describes backpropagation of error through layered networks. Its chain-rule structure supplies parameter derivatives efficiently; it does not guarantee the best possible solution of a nonconvex training problem. Later developments in data, computation, architectures, and optimization helped make deep networks broadly useful. The lecture proceeds through speech and vision successes, sequence models, attention, AlphaGo, and transformers.

Statistical AI emphasizes uncertainty, estimation, optimization, and generalization from observed data to new cases. Least squares, stochastic approximation, shortest-path algorithms, and decision processes have intellectual histories extending beyond AI. A probability model for blocked corridors supplies the \(p\) used earlier; a loss function turns that uncertain prediction into a decision. Model expressiveness and statistical validity answer different questions. Calibration compares stated probabilities with observed frequencies: among comparable predictions assigned blockage probability 0.2, a calibrated estimate would correspond to blockage about 20% of the time. That population condition requires an appropriate evaluation sample; a small sample need not exhibit exactly that fraction. A highly expressive network can still be badly calibrated in a new building.

For the robot, a useful synthesis is a learned visual representation, an explicit route graph, and a probabilistic model of occupancy. A symbolic rule alone may lack robust perception; a network alone may omit hard route constraints; a statistical estimate alone does not specify the action objective. The engineering task is to combine the needed capabilities and test their interfaces.

Foundation models change what is reused

A foundation model is trained on broad data and adapted to many downstream uses, as articulated in On the Opportunities and Risks of Foundation Models. Reusing a pretrained representation can reduce the amount of task-specific learning needed for our robot. It also propagates common limitations across applications. Strong general-purpose language behavior is evidence of useful capabilities, not direct validation of every downstream decision.

A text token is a discrete unit used to represent text, such as a word or a subword piece. Pretraining does not always mean predicting the next token. The lecture's broad account includes ELMo, BERT, and T5, whose training objectives differ. BERT's primary paper, §3.1, for example, describes predicting selected masked tokens using their context. Preserving that distinction matters when interpreting what a model was trained to infer; the objective alone does not certify that its generated statements are true.

Attention Is All You Need introduced the transformer architecture used by many subsequent systems. Attention will later connect to the pairwise tensor contractions developed below. Generating intermediate reasoning tokens spends additional inference computation; it does not automatically provide a faithful explanation or an independently checked proof.

The lecture closes its history with industrial scale and reduced disclosure. We do not reproduce speculative parameter or training-cost figures. The GPT-4 technical report explicitly withholds architectural and training details. Where disclosure ends, a textbook should identify the boundary rather than replace missing evidence with precise-looking numbers. Reproducibility and observed performance remain separate dimensions.

4. A tensor is an array plus a meaning for every axis 37:53

In the numerical-programming sense used here, a tensor is a multidimensional array of values. Its rank is the number of axes, and its shape lists their lengths. This array rank differs from matrix rank in linear algebra, which counts independent rows or columns. It also does not by itself assert the coordinate-transformation laws used to define tensors in differential geometry.

A scalar has shape () and array rank zero; a three-entry vector has shape (3,); a two-by-three matrix has shape (2,3). Shape is syntax. Axis meaning is the semantic contract. Two arrays of shape (8,8) may represent eight robots at eight times or eight spatial coordinates mapped to eight features. Equal shapes alone do not make their operations meaningful.

Let \(B\) be the number of independent robot observation sequences, \(T\) the number of time positions per sequence, and \(D\) the number of features per observation. All are positive integers in the running example. Write \(X\in\mathbb R^{B\times T\times D}\) for the feature tensor, where \(\mathbb R\) denotes real numbers. The entry \(X_{btd}\) is feature \(d\) at time \(t\) for sequence \(b\); indices begin at zero. For images, additional height, width, and channel axes may be needed before feature extraction.

The first axis is called a batch axis because it groups independent examples for common computation. NumPy does not know that meaning. It follows shape rules even if we accidentally treat robot identity as elapsed time. A batching implementation therefore needs a test that changing one robot's input leaves every other robot's output unchanged when the mathematical model says their decisions are independent.

Storage size and ownership are part of the model

A dense tensor of rank \(r\) with shape lengths \(n_1,\ldots,n_r\) has \(\prod_{j=1}^{r}n_j\) entries; the product multiplies the lengths of all axes. If each entry occupies \(q\) bytes, its raw element storage is \(q\prod_jn_j\) bytes, excluding metadata and temporary arrays. A batch of 32 RGB images of size 224 by 224 stored as four-byte floating point needs \(32\cdot224\cdot224\cdot3\cdot4=19{,}267{,}584\) bytes, or 18.375 MiB, where one MiB is \(2^{20}\) bytes. Additional intermediate tensors can easily exceed the input storage.

Arrays can be initialized with zeros, ones, random draws, or structured values such as an identity matrix. Those choices have meaning: zeros may represent missing initialization, a valid neutral value, or a false claim of perfect certainty. Random initialization requires an explicit random generator seed for reproducible teaching experiments. Saving parameters to disk preserves values; preserving axis conventions and preprocessing is also necessary to reproduce behavior.

A view is an array object that shares another array's underlying storage. Basic slicing and transposition commonly produce views. Modifying the view can therefore modify the original observations. NumPy's copies and views documentation distinguishes basic indexing, advanced indexing, and reshaping behavior; “every slice is a copy” and “every reshape is a view” are both unreliable blanket rules.

For the robot, diagnostic code that normalizes a shared observation view in place could alter the data later used by the policy. Copy when independent ownership is required, and otherwise treat observation arrays as immutable by convention. Our numerical lab checks both the existence of aliasing in a simple basic slice and the absence of input mutation in the actual policy computation.

Elementwise operations keep their input indices

An elementwise operation applies a scalar rule at each array position without summing an axis. For \(A=(1,4,9)\), squaring gives \(A^2=(1,16,81)\), taking the real square root gives \(\sqrt A=(1,2,3)\), adding the array to itself gives \(A+A=(2,8,18)\), and multiplying by the scalar 3 gives \(3A=(3,12,27)\). The corresponding NumPy expressions are A**2, np.sqrt(A), A+A, and 3*A. Real square roots require nonnegative entries; none of these operations automatically converts observations into valid probability estimates.

Triangular extraction instead keeps selected matrix positions and sets the others to zero. On a three-by-three matrix of ones, np.tril keeps entries on and below the diagonal, and np.triu keeps entries on and above it:

\[\operatorname{tril}(\mathbf 1)=\begin{bmatrix}1&0&0\\1&1&0\\1&1&1\end{bmatrix},\qquad\operatorname{triu}(\mathbf 1)=\begin{bmatrix}1&1&1\\0&1&1\\0&0&1\end{bmatrix}.\]

Here \(\mathbf 1\) denotes this matrix of ones, and both functions keep the main diagonal by default. These arrays record a positional selection rule; zeroing an entry does not by itself specify how a later normalized weighting operation should exclude it. That distinction becomes concrete in the masking example below.

5. Matrix multiplication and broadcasting encode decisions 47:30

Let \(K\) be the number of output scores per observation, and let \(W\in\mathbb R^{D\times K}\) be a weight matrix. Each column specifies how the input features contribute to one score. The output \(Y\in\mathbb R^{B\times T\times K}\) is defined entry by entry as

\[Y_{btk}=\sum_{d=0}^{D-1}X_{btd}W_{dk}.\]

The input-feature index \(d\) disappears because it is summed over. The sequence index \(b\), time index \(t\), and output index \(k\) remain. This is a contraction: multiplication followed by summation over a shared index. The equation explains both why the input-feature lengths must match and why the output shape has three axes.

For a two-feature observation \([2,1]\), take \(W=\begin{bmatrix}1&0\\0&2\end{bmatrix}\). Its two output scores are \(2\cdot1+1\cdot0=2\) and \(2\cdot0+1\cdot2=2\). A second observation \([0,3]\) produces \([0,6]\). In a neural model these can be intermediate scores; without a probability model they should not be described as probabilities.

NumPy expresses the batched contraction as X @ W. Matrix multiplication acts on the final two axes, with compatible leading axes handled by its batching rules. This differs from X * W, which requests elementwise multiplication and broadcasting. The matmul specification is the implementation authority; in particular, scalar multiplication uses *, not @.

Broadcasting is an index rule, not an instruction to duplicate data

A broadcast operation aligns array shapes from the trailing axis backward. Corresponding lengths are compatible when equal or when one is one; absent leading axes behave as length one. This rule is documented in NumPy's broadcasting guide. A length-\(K\) bias vector can be added to every output row, yielding \(Z_{btk}=Y_{btk}+c_k\), where \(c_k\) is the bias for output \(k\). Broadcasting often avoids materializing repeated copies, although the resulting output may still be large.

Return to the loss model. Let \(P\in[0,1]^{B\times T}\) contain blockage probabilities. Define \(Q\in\mathbb R^{B\times T\times2}\), whose final axis lists clear and blocked probabilities, by \(Q_{bt0}=1-P_{bt}\) and \(Q_{bt1}=P_{bt}\). Let \(C\in\mathbb R^{2\times2}\) have state rows and action columns:

\[C=\begin{bmatrix}1&3\\11&3\end{bmatrix},\qquad E_{bta}=\sum_{s=0}^{1}Q_{bts}C_{sa}.\]

Here \(s\) indexes the two possible states, \(a=0\) means go, \(a=1\) means wait, and \(E\) is expected loss. Multiplication \(Q@C\) yields shape \((B,T,2)\). Its go column is exactly \(1+10P\); its wait column is exactly 3. A tensor calculation has implemented the earlier decision model, including its assumptions, rather than silently inventing a new one.

At probabilities \([0,0.1,0.2,0.4,1]\), expected go losses are \([1,2,3,5,11]\), while waiting always costs 3. The action sequence with our explicit tie convention is go, go, wait, wait, wait. A generic minimum-index selector would choose go on equality because go appears first. This small discrepancy is why a policy specification includes tie behavior.

The threshold is also a numerical implementation issue. In binary floating point, the value immediately below 0.2 is 0.19999999999999998. It should select go, but the computed loss 1 + 10*p can round to 3.0, creating a false tie with waiting. Our policy therefore compares the validated floating-point probability directly with 0.2; it does not select actions by comparing the rounded loss outputs. The stored value 0.2 selects wait. Converting a more precise input to floating point can itself discard information near the threshold, so this executable contract applies to the converted value. Accurate execution of that contract does not establish that the robot's probability estimate is accurate.

Reduction and masking change the question being answered

A reduction aggregates an axis using an operation such as sum, mean, minimum, or maximum. Taking a mean over time asks about average performance; taking a maximum asks about the worst observed time. If robot losses are \([1,1,10]\), their mean is 4 and maximum 10. Neither alone says whether the rare high-loss event is acceptable.

A triangular mask marks allowed interactions between time positions. For query position \(i\) and key position \(j\), a causal mask permits the set \(M_i=\{j:j\le i\}\). To see the operation in the smallest setting, let \(z_{ij}\) be finite real scores, and assume the allowed set is nonempty. The softmax normalization restricted to allowed keys defines weights

\[w_{ij}=\begin{cases}\displaystyle\frac{\exp(z_{ij})}{\sum_{k\in M_i}\exp(z_{ik})},&j\in M_i,\\0,&j\notin M_i.\end{cases}\]

Here \(k\) indexes the allowed keys in the denominator. These nonnegative weights sum to one. With scalar values \(v_j\), the weighted output is \(y_i=\sum_jw_{ij}v_j\). Consider query 0, two scores \((0,0)\), and values \((2,10)\). Without a mask the weights are \((1/2,1/2)\) and the output is 6. Replacing the forbidden second score with zero changes nothing. Excluding it gives weights \((1,0)\) and output 2. Assigning negative infinity before softmax implements that exclusion because its exponential is zero; it must not leave a row with no allowed finite score.

This mask blocks the direct contribution of future key positions. A causal guarantee for a whole computation additionally requires the allowed query, key, and value representations, and every other path into the output, to depend only on the available prefix. A mask cannot erase future information already present in an allowed value. The example is an original teaching construction connecting the lecture's triangular-array primitives to the decoder masking operation in Attention Is All You Need, §3.2.3; it is not a measured result from a trained attention model.

6. Named axes make efficient computation auditable 51:56

The explicit contraction for \(Y\) requires \(BTKD\) multiplications and \(BTK(D-1)\) additions in the straightforward dense algorithm. A triple or quadruple Python loop and a library matrix product can perform the same mathematical work while taking very different wall-clock time. Optimized kernels exploit compiled loops, memory locality, vector instructions, and sometimes hardware parallelism. Standard NumPy arrays reside on the CPU; expressing a computation as tensors does not itself move it to a GPU.

Batching can also increase memory consumption or compute unneeded outputs. If only one robot requires a decision, waiting to fill a large batch may worsen its latency. Tensorization should be evaluated with a correctness check, a memory estimate, and a measurement on representative sizes. This chapter reports arithmetic and behavioral checks, not an unmeasured speedup claim.

Contraction notation exposes accidental interactions

The einops einsum interface permits descriptive axis names. The earlier score transform can be written einsum(X, W, 'batch time feature, feature score -> batch time score'). An axis appearing in the inputs but absent from the output is summed out. This makes the correspondence with the defining equation visible.

Suppose \(U\in\mathbb R^{B\times I\times D}\) and \(V\in\mathbb R^{B\times J\times D}\) represent two sets of feature vectors from each robot sequence. Here \(I\) and \(J\) are the numbers of positions in the two sets. Pairwise similarity within each sequence is \(S_{bij}=\sum_d U_{bid}V_{bjd}\). Named notation is 'batch first feature, batch second feature -> batch first second'. Keeping batch in the output preserves separate robots. Omitting it would aggregate their products and answer a different question.

Take one sequence with \(U=[[1,0],[0,1]]\) and \(V=[[1,1],[2,0]]\). Its similarity matrix is \([[1,2],[1,0]]\): each entry is a dot product of one row from each input. This is the core contraction used in attention scores before additional scaling, masking, and normalization. It is not a complete attention layer and does not claim that raw similarity measures relevance correctly.

The einops reduce interface makes aggregation equally explicit: reduce(E, 'batch time action -> batch action', 'mean') retains robot and action identity while averaging over time. For one robot with probabilities 0.1 and 0.4, the two expected-loss vectors are [2, 3] and [5, 3], so the output is [3.5, 3]. This compares the time-averaged losses of always choosing each action. It differs from adapting the action at each time: choosing go first and wait second averages (2 + 3)/2 = 2.5. Reduction and decision selection do not generally commute; their order encodes what choices the policy is allowed to make.

Rearranging changes the address scheme, not the data's information

The rearrange operation expresses axis permutation and factorization. Suppose the \(D=8\) features of each observation represent \(H=2\) groups of \(F=4\) features, so \(D=HF\). Group \(h\), local feature \(f\), corresponds to flattened feature \(d=hF+f\). The pattern 'batch time (head feature) -> batch time head feature', with head=2, exposes this structure.

That factorization is an assumption about ordering. A different flattening convention, \(d=fH+h\), gives a different arrangement with exactly the same sizes. A round-trip flatten/unflatten check is necessary but not sufficient to establish the intended semantics: two mutually inverse wrong conventions still round-trip. Check a labeled element as well. Under our convention, flattened feature 5 belongs to group 1, local feature 1.

Once separated, each group can use a common transform before being flattened again. An incompatible factorization, such as dividing eight features into three equal groups, must fail explicitly. Rearranging preserves the collection of values; a reduction discards distinctions by combining them. Confusing these operations can quietly destroy the information needed to associate predictions with individual robots.

7. An executable loss model with an explicit contract

The accompanying numerical_lab.py implements the expected-loss contraction and the probability-threshold decision rule. Its input is a nonempty rectangular nested sequence of real blockage probabilities, one row per robot and one column per time. The validator rejects booleans and nonreal values, checks each original value against \([0,1]\), and then converts accepted values to finite floating point. Out-of-range values, nonfinite values, ragged rows, and rejected scalar types raise ValueError. The returned loss vectors and action rows are fresh nested lists; inputs are never modified. Loss arithmetic is rounded, and action selection uses the converted probabilities with the boundary convention explained above. These functions have no network or filesystem effects.

The implementation uses the Python standard library to make the original model executable without installing a numerical framework. An optional NumPy check verifies equivalence to the batched contraction when NumPy is available. Shape conventions and checks transfer to a tensor library; the small loop implementation makes no performance claim.

from numerical_lab import expected_losses, choose_actions

probabilities = [[0.0, 0.1, 0.2, 0.4, 1.0]]
losses = expected_losses(probabilities)
assert losses == [[[1.0, 3.0], [2.0, 3.0], [3.0, 3.0],
                   [5.0, 3.0], [11.0, 3.0]]]
assert choose_actions(probabilities) == [
    ["go", "go", "wait", "wait", "wait"]
]

These checks verify arithmetic, axes, tie behavior, rejection of invalid values, and absence of input mutation. They cannot verify whether a real model's probability estimates are calibrated. A deployment evaluation would compare predicted probabilities against outcomes under specified operating conditions, and separately measure the consequences of the chosen policy. A unit test proves neither of those empirical properties.

Our model also omits delayed effects: waiting could reveal new information, moving could create a hazard, and today's action could change tomorrow's route. Those omissions motivate sequential decision models later in the course. They do not invalidate the one-step calculation; they define the boundary within which it answers the intended question.

8. Exercises and fully worked solutions

  1. Decision threshold. Change clear-path go loss to 2, blocked-path go loss to 22, and waiting loss to 5. Derive the threshold and choose at probabilities 0.1 and 0.2. Explain what changing the penalty does not establish.
  2. Representation counterexample. A linear threshold classifier labels \((0,0)\) and \((1,1)\) negative, but \((1,0)\) and \((0,1)\) positive. Prove that no weights and threshold can satisfy these labels if positive means a strictly positive affine score and negative means a nonpositive score.
  3. Shape and computation. For \(X\) of shape \((3,5,4)\) and \(W\) of shape \((4,2)\), give the output shape and straightforward multiplication count. Can a bias of shape \((3,)\) be added to that output by ordinary trailing-axis broadcasting?
  4. Storage and ownership. A basic NumPy slice shares its parent's storage. Explain why modifying it can corrupt a later policy input. How does a copy change this, and what does it fail to protect against?
  5. Index semantics. Two robots have one feature vector each: \(U_0=[1,0]\), \(V_0=[1,0]\), \(U_1=[0,2]\), and \(V_1=[0,3]\). Compare keeping and reducing the robot axis in their dot products. Which output supports independent decisions?
  6. Rearrangement and evaluation. Split eight ordered features into two groups of four using \(d=4h+f\). Locate feature 6. Explain why a reversible reshape does not validate a perception model, then propose one numerical and one empirical check.
Worked solutions

1. Expected go loss is \(2(1-p)+22p=2+20p\). Comparing with 5 gives \(p\lt3/20=0.15\), with waiting at equality under our convention. At 0.1, go costs 4 and wins; at 0.2, it costs 6 and loses. Increasing a collision penalty changes the optimal action within the stated model. It does not establish that either the probability estimate or the penalty captures real consequences.

2. Let weights be \(w_1,w_2\) and bias be \(b\). The origin's negative label requires \(b\le0\); the other negative example requires \(w_1+w_2+b\le0\). Positive examples require \(w_1+b>0\) and \(w_2+b>0\). Adding them gives \(w_1+w_2+2b>0\). But the negative constraints imply \(w_1+w_2+2b\le b\le0\), a contradiction. Training cannot find parameters that do not exist. Nonlinear features or a richer model family are required.

3. Contract the shared length-four feature axis, preserving robot, time, and output axes. The result is \((3,5,2)\). There are \(3\cdot5\cdot2\cdot4=120\) multiplications and 90 additions in the direct algorithm. A \((3,)\) bias fails because its trailing length 3 conflicts with output length 2. A bias per robot would need shape \((3,1,1)\); a bias per output would have shape \((2,)\). Selecting the shape follows the intended meaning.

4. A view changes indexing metadata while retaining shared storage, so a write through the view reaches the original values. A copy creates independent storage, allowing separate mutation. It does not repair incorrect preprocessing, stale observations, or an already corrupted parent. Ownership prevents a class of interference bugs; it does not certify data validity. Avoiding mutation in the policy helper provides a separate, directly testable guarantee.

5. Keeping robot identity yields dot products \([1,6]\). Reducing robot identity adds them to 7. The scalar loses the association between each robot and its score, so it cannot supply independent decisions without additional information. Broadcasting 7 back to both robots restores the old shape but not the lost information. This is a concrete example of shape-correct code implementing the wrong mathematical question.

6. Division with remainder gives \(6=4\cdot1+2\), so feature 6 belongs to group 1 and local feature 2. A reshape only reorganizes existing values; it does not determine whether those values predict blockage. Numerically, verify both round-trip equality and that a labeled feature reaches the intended location. Empirically, evaluate predictions on held-out robot trajectories from the intended operating conditions, without counting repeated frames as independent environments. Report probability quality and policy outcomes separately.
